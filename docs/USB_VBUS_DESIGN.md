# USB の設計: VBUS の検出と、D+ のプルアップの制御（H5 / H7 の対応）

オーナーの指示（2026-11-17）: **H5（PC の電源が OFF の間の D+）と H7（`J3` の実物）は、実機の測定をせず、USB の仕様に沿った設計で進める。** この文書は、その設計。測定をしないので、**仕様の規則を、設計で必ず満たす**（測って「問題なし」と確かめることはしない）。

## 1. 仕様の要求（一次。USB 2.0 仕様書 Revision 2.0、2000-04-27。原文は `docs/HW_VERIFY.md` H.0）
- §7.1.5.1: プルアップ（D+ に 1.5 kΩ ±5%、VTERM = 3.0〜3.6 V）の電圧源は、**ケーブルの電源（VBUS）から作るか、VBUS で制御する**こと。**VBUS が外れたとき、プルアップは、データ線に電流を出さない**。
- §7.2.1: デバイスは、**VBUS がないとき、D+/D- のプルアップに給電してはならない**。**VBUS が外れたら、10 秒以内に**プルアップへの給電を外す。
- ホスト・ハブの下流ポートは、15 kΩ ±5% のプルダウン（§7.1.5.1）。VBUS の電圧は、ハブの下流ポートで、高電力ポート 4.75〜5.25 V、低電力ポート 4.40〜5.25 V（§7.2.1 の表。**同じ配布物の ECN「USB 2.0 VBUS Max Limit」で、上限は 5.50 V に拡大**）。

## 2. この基板の状況
- `J3` は、4 ピン（1 = `VCC_5V`、2 = D−、3 = D+、4 = GND）。**ピン 1 は、ボードの 5V 電源**で、PC の VBUS には繋がない（オーナー決定 2026-11-08。H3）。配線は 3 本（D+、D−、GND）。
- ESP32-P4 の HS OTG には、**ハードウェアの VBUS 検出がない**（H2）。ファームは、`GOTGCTL` の BVALID / VBVALID の上書きで、B セッションを有効にして列挙する（`CONFIG_USB_DEVICE_BVALID_OVERRIDE`）。**この上書きは、VBUS の有無に関係なく、プルアップを入れる**。
- したがって、**3 本配線のままでは、PC が OFF（VBUS なし）でも、プルアップが入り続け、§7.1.5.1・§7.2.1 に反する**。測定は、この反しているかの程度を知るためのもので、**規則を満たすには、測定の結果に関係なく、VBUS を検出して、プルアップを制御する必要がある**。

## 3. 設計: VBUS を検出して、プルアップを制御する（おすすめの 1 案。`HW_VERIFY.md` H.0 の対策案 1）
### 3.1 ハードウェア（オーナーが決める。部品の値は、この文書では決めない）
- **PC の VBUS を、`J3` のピン 1 とは別の線で、ESP32-P4 の GPIO に入れる**（`J3` のピン 1 は、ボードの 5V なので、使わない）。**VBUS の線に、分圧の抵抗（R1: VBUS 側、R2: GND 側）を入れる**。R2 は、**線が抜けたとき、GPIO を 0 に引く**役目も持つ（VBUS なし = 0 = 安全側）。
- **分圧の値は、回路図と、データシート、USB 仕様の値から計算できる**（オーナー指摘 2026-11-17: 回路図で分かる）。入力の値と出典:

| 値 | 内容 | 出典 |
|---|---|---|
| `VDD`（GPIO の I/O 電源） | `ESP_3V3` ≒ **3.27 V**（FB 0.8 V、R18 = 40.2 kΩ、R24 = 13 kΩ から 0.8 × (1 + 40.2/13)） | 回路図 1 ページ（`HW_VERIFY.md` E6）。**[計算]**。実測なし。FB の 0.8 V は回路図の注記で、U1 のデータシートで未確認 |
| `VIH`（最小） | **0.75 × VDD** ≒ 2.46 V | ESP32-P4 データシート v0.7（preliminary。`docs/HW_STATE.md` の引用）。**この環境から、データシートの原文は取得できず、未確認** |
| `VIL`（最大） | **0.25 × VDD** ≒ 0.82 V（データシート v0.7 の一般的な値。`TODO(hw-verify)`: 原文で確認） | 同上 |
| GPIO に入れてよい上限 | **VDD 以下**（保護ダイオードを導通させない保守的な値。**データシートの絶対最大定格は、未確認**） | 設計の方針 |
| `VBUS`（PC のルートポート） | **4.75〜5.50 V**（下限: 高電力ポート。上限: **ECN「USB 2.0 VBUS Max Limit」で 5.25 V から 5.50 V に拡大**。Type-C の 3 A の供給側の電圧降下を見込むため） | USB 2.0 仕様書 §7.2.2 の表と、同じ配布物の ECN（原文で確認済み）。**上限は 5.50 V で設計する**（CodeRabbit の指摘、2026-11-17） |
| 抵抗の許容差 | 1%。`VDD` の許容差は ±5% を見る | 設計の方針 |

  - **条件**: ① `VBUS` = 4.75 V のとき、GPIO の電圧が、`VIH` の最大（= 0.75 × VDD の上限）以上。② `VBUS` = **5.50 V** のとき、GPIO の電圧が、`VDD` の下限以下。③ `VBUS` がない（0 V、または線が抜けた）とき、R2 が GPIO を 0 V に引く（`VIL` 以下）。
  - **結果（E24、1% の抵抗）: R1（VBUS 側）= 120 kΩ、R2（GND 側）= 150 kΩ**。分圧比は 0.551〜0.561（許容差を含む）。① `VBUS` = 4.75 V で 2.62 V 以上（`VIH` の最大 2.53 V〔`VDD` ±3%〕に対し、余裕 0.09 V）。② `VBUS` = 5.50 V で 3.08 V 以下（`VDD` の下限 3.18 V に対し、余裕 0.09 V）。R1 + R2 = 270 kΩ なので、`VBUS` への負荷は、最大で約 0.02 mA（5.50 V ÷ 270 kΩ）。
  - **`VDD` の許容差が ±5% の場合は、E24・1% の 120 kΩ / 150 kΩ の余裕が 0.03 V に減る**（成立はする）。**余裕を取るなら、0.5% の E96 の抵抗 R1 = 130 kΩ、R2 = 162 kΩ**（`VDD` ±5% で余裕 0.045 V、±3% で 0.095 V）。**`ESP_3V3` の許容差（FB の基準電圧の許容差）は、データシートで未確認**なので、**0.5% の抵抗をおすすめする**。
  - **ウィンドウは狭い**（分圧比の上限と下限の比が 1.07 倍ほど）。許容差 5% の抵抗では、解がない。**抵抗は 1% 以下を使う**こと。VBUS の上限を 5.25 V で計算すると、5.50 V の VBUS で、GPIO が `VDD` を超える（指摘のとおり）。
  - **`VBUS` = 4.40 V（低電力ポート。バス給電のハブの下流ポート）は、想定しない**（その場合は、ウィンドウが成立しない。ターゲット PC の**ルートポート**に繋ぐこと。ハブの下流に繋ぐ場合は、設計の見直しが要る）。
  - **ボードの電源が入っていないとき**（PC は ON）: `VBUS` → R1 → GPIO の保護ダイオード → `VDD` の経路で、約 0.04 mA が流れる（(5.50 V − 約 0.6 V) ÷ 120 kΩ）。小さいが、**ボードが半分だけ起動する状態を作りうる**ので、**ボードの電源を入れてから、PC に繋ぐ**運用とする。`TODO(hw-verify)`。
  - **ESD**（H4）: 抜き差しで、GPIO を傷めないこと。**R1 が直列抵抗を兼ねる**（120 kΩ）。クランプ素子の要否は、オーナーが決める。
  - **`TODO(hw-verify)`（値は計算で、実測なし）**: ESP32-P4 のデータシート（最終版）の `VIH` / `VIL` / 絶対最大定格、`ESP_3V3` の実測値（約 3.27 V は計算）。これらが、上の仮定と違ったら、この計算をやり直す（`docs/USB_VBUS_DESIGN.md` のスクリプト相当は、この表の式）。
- **GPIO**（回路図から。`P1`「`PICO-2*20`」ヘッダ）: **推奨は GPIO18（P1 の 4 番）**。理由: ① ヘッダに出ている。② GPIO16 / 17（X630 の RESET / INT。`HW_STATE.md` で、電源ドメインが `VDDPST_2` = `ESP_3V3` と確認）の隣で、**同じ `VDDPST_2` の領域とみられる**（回路図の ESP32-P4 のシンボルで、GPIO9〜19 が `VDDPST_2` の並び。**`TODO(hw-verify)`: データシート Table 2-1 で、GPIO18 のドメインを確認**）。③ JTAG（GPIO2〜5）、USB（GPIO24〜27）、ストラップ（GPIO34〜38）、コーデックの I2S（GPIO9〜13）、RMII（Ethernet）、I2C（GPIO7 / 8）ではない。④ `docs/PLAN.md` 4.4 の「ATX の A0/A1・Ē、KVM の LED」の GPIO の番号は、P6 で確定する（**重ならないことを、P6 で確認する**）。**代案: GPIO14（P1 の 9 番）、GPIO15（7 番）、GPIO19（2 番）**。Kconfig `USB_DEVICE_VBUS_SENSE_GPIO`（既定 -1 = 検出なし）で指定する。
- 線は、3 本から 4 本になる（PC の VBUS 用の 1 本が増える）。**VBUS の線は、`J3` に繋がず、GPIO の分圧回路にだけ繋ぐ**（H3 の決定の趣旨 = ボードの 5V と PC の VBUS を繋がない、を保つ）。

### 3.2 ファームウェア（`usb_vbus_ctrl`、純 C + `usb_hid` の結線）
- **起動時は、プルアップなし（切断）**。VBUS が一定時間、続けて検出されたら、**接続**（`tud_connect`）。VBUS が一定時間、続けて検出されなければ、**切断**（`tud_disconnect`）。
- **安全側の規則**: GPIO の読み出しが失敗したときは、VBUS なしとみなす（切断の側）。切断の呼び出しが失敗したときは、**成功するまで毎回、再試行する**（接続の呼び出しの失敗は、切断のまま再試行）。
- **10 秒の保証と、切断が失敗し続けるとき**（CodeRabbit の指摘、2026-11-17）: **10 秒の要件は、切断の操作が成功することが前提**。`tud_disconnect` は、`DCTL.sftdiscon` を書くだけのローカルのレジスタ操作で、ドライバが初期化されていないとき以外は、通常は失敗しない。**失敗が続くとき**: 切断を再試行しつつ、**VBUS が外れたと判断してから `force_off_after_ms`（既定 2000 ms、最大 3000 ms）を超えても切断が成功しなければ、強制遮断**（`FORCE_OFF`）を出す。`usb_hid` は、`DCTL.sftdiscon` を**直接**書く。それも失敗するなら、**USB のドライバを停止**（`tinyusb_driver_uninstall`）して、UTMI の PHY を落とす（最後の手段）。強制遮断は、成功するまで毎回、再試行する。**すべての手段が失敗する故障（レジスタに書けない）では、仕様を満たせない**。この場合は、`ESP_LOGE` と、`usb_hid` の統計に残す（故障として扱う）。
- **タイミング**（仕様の 10 秒の上限から決める。`TODO(hw-verify)`: 既定値は、実機で確認）: VBUS が外れてから切断（または強制遮断）の操作を始めるまでは、**デバウンス（≤ 4 秒）+ サンプル周期（≤ 2 秒）+ 強制遮断までの待ち（≤ 3 秒）≤ 9 秒 < 10 秒**。接続側のデバウンス（VBUS の立ち上がりが安定するまで）は、短くてよい。
- 検出なし（`USB_DEVICE_VBUS_SENSE_GPIO = -1`、既定）のときは、**いまの動作**（初期化の最後に接続する。`USB_DEVICE_START_DISCONNECTED` で、切断のまま起動もできる）。**この場合、仕様の §7.2.1 を満たさない**ことを、Kconfig の help に書く（H5 の懸念が残る）。

## 4. 他の案（おすすめ順。`HW_VERIFY.md` H.0 から。測定なしでも決められる）
1. **VBUS の検出（3 章）**: 仕様の規則そのものを満たす。部品と線が増える。
2. **ATX の状態に連動して切断**: `kvm_ctrl` が OFF にしたら切断、ON にしたら接続。手動での電源の変化は検出できない（部分的）。
3. **既定は切断のまま、API / ビューアから接続**（`USB_DEVICE_START_DISCONNECTED`）: 操作が 1 つ増える。
4. **PC が OFF の間は、ケーブルを抜く運用**: ソフトの変更なし。
5. データ線へのダイオード・アナログスイッチ: HS の信号品質（H6）を損なうので、**おすすめしない**。

## 5. H5 / H7 の扱い（測定なし）
- **H5**: この設計（3 章）で、仕様の規則を満たす。**実機の測定は、しない**（オーナー決定 2026-11-17）。残る未確認: データシート（最終版）の `VIH` / `VIL` / 絶対最大定格による、分圧の値（120 kΩ / 150 kΩ）の再確認、VBUS の検出が実機で働くこと（Antigravity が、GPIO にジャンパで 3.3 V / GND をあてて、接続・切断の遷移を確認できる。PC は要らない）、D+ の実際の電圧（測らない）。
- **H7**: `J3` の実物（形状・ピッチ・部品番号）は、ケーブルを作るときに、オーナーが確認する（`HW_VERIFY.md` H.0 の H7 の手順）。**設計には影響しない**ので、`TODO(hw-verify)` のまま、ブロックしない。
