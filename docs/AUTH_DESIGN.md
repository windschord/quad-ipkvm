# Authentication Design (auth_logic)

## 概要

ESP-KVM の認証システムは、単一アカウント (`admin`) に対して、パスワードによる初回設定と、セッショントークンによる認証を提供します。本モジュールは ESP-IDF に依存しない純粋な C で実装され、ホストテストおよびファジングで徹底的に検証されます。

## 状態遷移

システムは以下の 2 つの状態を持ちます。
1. `NEEDS_SETUP`: 初期状態。パスワードが未設定。この状態ではパスワード設定の API のみ許可され、他のすべての認証付き API は 403 / 拒否されます。
2. `READY`: パスワード設定済み。セッションの発行と検証が可能です。

設定は1度だけ受け付けられ、二重設定はシステムレベルで防ぎます（競合対策）。

## パスワードポリシーと保存形式

*   **ユーザー名**: `admin` に固定します。
*   **最小長**: 10 文字（`auth_logic_config_t` で設定可能）。短すぎるパスワードは辞書攻撃に弱いため。
*   **最大長**: 128 バイト（DoS 対策）。PBKDF2 は入力長に比例して処理時間が長くなるため、長過ぎる入力を事前に弾きます。
*   **拒否リスト**: ユーザー名と同じ（`admin`）や、よくある短い弱いパスワード（例: `password`、`1234567890` など）は拒否します。構成文字種の強制（大文字小文字記号を含む等）は行いません。
*   **保存形式**: バイナリ形式で保存します。
    *   バージョン番号 (1 バイト)
    *   ソルト (16 バイト)
    *   反復回数 (uint32_t, リトルエンディアン)
    *   ハッシュ (32 バイト, SHA-256)
*   **反復回数の下限**: システム全体として 10,000 を下限とします。これ未満の設定が渡された場合は初期化を拒否します。
*   **既定の反復回数**: `TODO(hw-verify)`。ESP32-P4 上での PBKDF2-HMAC-SHA256 の計算時間を計測し、1回のログイン試行に妥当な時間（例: 0.5〜1秒）かかる値に設定します。OWASP の推奨はより大きい（数万〜数十万）ですが、マイコンの計算能力に合わせて調整が必要です。将来的に安全性を高めるため、反復回数は保存形式に含まれており、変更（再ハッシュ）が可能です。
*   **乱数生成**: フェイルクローズ（fail-closed）。ソルトやトークンの生成時に乱数取得が失敗した場合は直ちにエラーとし、弱い乱数で処理を続行することはしません。

## セッション管理

*   **トークン**: ログイン成功時に発行される 32 バイトの乱数。クライアントには Base64URL エンコードされて Cookie に保存されます。
*   **状態保持**: サーバー側（セッション表）には、トークンそのものは保存せず、トークンの **SHA-256 ハッシュ値のみ**を保存します。これにより、メモリダンプや情報漏洩が発生しても、有効なトークンそのものは盗まれません。
*   **ライフサイクル**:
    *   最大セッション数に達した場合、新しいログインは最も古いセッションを追い出すか、拒否します（実装では一番古いものを追い出す LRU 的なアプローチか、または失敗とします。本実装では一番古いセッションを追い出します）。
    *   アイドルタイムアウトと絶対期限（それぞれ config で設定可能）を持ち、期限切れのセッションは無効になります。
    *   ログアウト、および全セッション失効（パスワード変更時）をサポートします。

## レート制限と DoS 対策

ログイン試行にはレート制限をかけ、ブルートフォース攻撃を防ぎます。

1.  **判定タイミング**: パスワードのハッシュ計算（PBKDF2）の **前** にロックアウト状態を判定します。ロックアウト中のリクエストに対して重い計算を行うと DoS 攻撃になるためです。
2.  **キー**: 送信元の IP アドレス等を表す整数値（`source_ip`）ごとに失敗回数を記録します。
3.  **追い出しポリシー**: レート制限の記録表が満杯になった場合、新しい IP からの失敗は「全体の制限（グローバルカウンタ）」に集約されます。
    *   **重要**: ロックアウト中や失敗カウント中のエントリは、表から絶対に追い出されません。期限切れ、または失敗のないエントリのみが再利用されます。これにより、攻撃者が偽の IP アドレスから大量にリクエストを送り、既存のロックアウトエントリを追い出して制限を解除する攻撃を防ぎます。
4.  **バックオフとロックアウト**: 失敗回数に応じて遅延（またはロックアウト）時間を延長します。設定値は `TODO(hw-verify)` であり、実機の処理能力を考慮して決定します。成功時にカウントはリセットされます。
