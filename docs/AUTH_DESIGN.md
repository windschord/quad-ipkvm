# Authentication Design (auth_logic)

## 概要

quad-ipkvm の認証システムは、単一アカウント (`admin`) に対して、パスワードによる初回設定と、セッショントークンによる認証を提供します。本モジュールは ESP-IDF に依存しない純粋な C で実装され、ホストテストおよびファジングで徹底的に検証されます。

## スレッド安全性

`auth_logic` は単体ではスレッドセーフではありません。呼び出し側は、すべての API アクセスを 1 つのミューテックス等で直列化する必要があります。これは、パスワードの二重設定やセッション表・レート制限表への競合を防ぐためです。なお、PBKDF2 ハッシュ計算中もこのロックを保持し続ける必要があるため、他タスクのブロッキング時間（0.5〜1秒程度）に注意してください。

## 状態遷移

システムは以下の 2 つの状態を持ちます。
1. `NEEDS_SETUP`: 初期状態。パスワードが未設定。この状態ではパスワード設定の API のみ許可され、他のすべての認証付き API は 403 / 拒否されます。
2. `READY`: パスワード設定済み。セッションの発行と検証が可能です。

設定は1度だけ受け付けられ、二重設定はシステムレベルで防ぎます（競合対策）。

## パスワードポリシーと保存形式

*   **ユーザー名**: `admin` に固定します。
*   **最小長**: 10 文字（`auth_logic_config_t` で設定可能）。短すぎるパスワードは辞書攻撃に弱いため。
*   **最大長**: 128 バイト（DoS 対策）。PBKDF2 は入力長に比例して処理時間が長くなるため、長過ぎる入力を事前に弾きます。
*   **拒否リスト**: ユーザー名を（大文字小文字を区別せず）含むもの、同一文字の連続（例: `aaaaaa`）、昇順降順の並び（例: `123456`）、および事前定義された一般的な弱いパスワードのリストを拒否します。構成文字種の強制（大文字小文字記号を含む等）は行いません。
*   **保存形式**: バイナリ形式で保存します。
    *   バージョン番号 (1 バイト、現状 2)
    *   ソルト (16 バイト)
    *   反復回数 (uint32_t, リトルエンディアン)
    *   ハッシュ (32 バイト, SHA-256)
    *   整合性ダイジェスト (8 バイト、ペイロードの SHA-256 の先頭 8 バイト)
*   **反復回数の下限**: システム全体として 10,000 を下限とし、上限を 10,000,000 とします。
*   **既定の反復回数**: 仮定として0.5〜1秒を目標としていますが、`TODO(hw-verify)` です。ESP32-P4 上での PBKDF2-HMAC-SHA256 の計算時間を計測し、決定してください。
*   **乱数生成**: フェイルクローズ（fail-closed）。ソルトやトークンの生成時に乱数取得が失敗した場合は直ちにエラーとし、弱い乱数で処理を続行することはしません。
    *   `TODO(hw-verify)`: `psa_generate_random()` が真の乱数を返すための前提要件（PSA Crypto API の初期化、エントロピープールの状態、および基盤となるハードウェア RNG の要件）が ESP32-P4 上で満たされているか、ESP-IDF v6.0.1 のドキュメントで確認が必要です。

## セッション管理

*   **トークン**: ログイン成功時に発行される 32 バイトの乱数。クライアントには Base64URL エンコードされて Cookie に保存されます。
*   **状態保持**: サーバー側（セッション表）には、トークンそのものは保存せず、トークンの **SHA-256 ハッシュ値のみ**を保存します。これにより、メモリダンプや情報漏洩が発生しても、有効なトークンそのものは盗まれません。
*   **ライフサイクル**:
    *   最大セッション数に達した場合、新しいログインは最も古いセッションを追い出すか、拒否します（実装では一番古いものを追い出す LRU 的なアプローチか、または失敗とします。本実装では一番古いセッションを追い出します）。
    *   アイドルタイムアウトと絶対期限（それぞれ config で設定可能）を持ち、期限切れのセッションは無効になります。
    *   ログアウト、および全セッション失効（パスワード変更時）をサポートします。

## レート制限と DoS 対策

ログイン試行にはレート制限をかけ、ブルートフォース攻撃を防ぎます。

1.  **判定タイミング**: パスワードのハッシュ計算（PBKDF2）の **前** にロックアウト状態を判定します。ロックアウト中のリクエストに対して重い計算を行うと DoS 攻撃になるためです。
2.  **キー**: 送信元の IP アドレス等を表す 32 ビットの整数値（`source_ip`、IPv4 を想定し、IPv6 の場合は呼び出し側で畳み込むことによる衝突許容）ごとに記録します。
3.  **時間窓と減衰**: 指定された時間窓 (`rate_limit_window_ms`) を基準に失敗を数え、窓を過ぎた失敗エントリはカウントと連続ロックアウト回数をリセットします。
4.  **指数的バックオフ**: 連続してロックアウトされるたびに、ロックアウト時間が `base_lockout_ms * 2^(n-1)` のように指数的に延びます（最大 `max_lockout_ms`）。
5.  **追い出しとグローバル集約ポリシー**: レート制限表が満杯になった場合、時間窓が過ぎた古いエントリを追い出します。もし全てがアクティブな失敗・ロックアウトで埋まっている場合は、新しい IP からの失敗を「グローバルカウンタ」に集約します。
    *   グローバル制限は固有の時間窓と、より高い失敗許容数を持ちます。
    *   LAN 内の攻撃者が多数の送信元を偽装してグローバル制限を引き起こし、正当な持ち主を一時的に締め出す（DoS）リスクは残存します。これを回避するには、システムをインターネットに直接公開せず VPN 経由とするなどの前提が必要です。
